# 계정 단위 데이터 테스트 툴

## 목적

`platform-server`가 모든 사용자 데이터를 HIVE 세션의 `subject`별로 분리하는지 한 명이 두 계정을 번갈아 로그인하며 수동 확인하지 않고 반복 검증한다. 이 툴은 AWS, HIVE, NICEPAY 실계정과 실데이터를 사용하지 않는다. 메모리에 두 개의 독립 계정을 만들되 실제 Express 라우트, 인증 미들웨어, 저장 서비스와 상점 서비스를 그대로 호출한다.

## 실행

```powershell
Set-Location platform-server
pnpm test:account-scope
```

CI나 다른 프로그램에서 결과를 읽을 때는 JSON 출력을 사용한다.

```powershell
pnpm test:account-scope -- --json
```

모든 검사가 통과하면 종료 코드는 `0`, 하나라도 실패하면 `1`이다. 따라서 GitHub Actions나 배포 전 검사에 그대로 연결할 수 있다. 일반 `pnpm test`와 `pnpm check`에도 같은 시나리오의 회귀 테스트가 포함된다.

## 자동 검사 범위

1. 일반 상점 카탈로그는 비로그인 조회가 가능하고 계정 경제 조회는 차단되는지 확인한다.
2. A/B 세션이 서로 다른 `subject`로 식별되고 신규 저장이 각각 생성되는지 확인한다.
3. A의 설정과 서버 산출 업적 상태가 B에 섞이지 않는지 확인한다.
4. 전체 프로필 저장으로 일반 돈·재료·도구·누적 통계·임의 업적을 조작할 수 없는지 확인한다.
5. A의 일반 상점 구매와 멱등 재시도가 B의 돈·재료에 영향을 주지 않는지 확인한다.
6. 서버 발급 영업일과 소별 판매·사용량 검증을 거친 A의 하루 정산·누적 통계가 B의 진행에 영향을 주지 않는지 확인한다.
7. A의 Mock 프리미엄 구매·황금 틀 장착·구매 내역이 B에 노출되지 않고, B의 미보유 장착이 거부되는지 확인한다.
8. A의 진행 초기화가 계정 업적·설정·프리미엄 보유품을 보존하는지 확인한다.
9. 기존 세션 폐기 후 같은 `subject`로 재로그인했을 때 A 데이터가 복원되는지 확인한다.

## 해석과 한계

- `PASS`는 서버 코드의 계정 키 사용과 API 경계가 정상이라는 뜻이다.
- 이 검사는 의도적으로 로컬 인메모리 저장소를 사용하므로 AWS 자격 증명이 필요 없고 운영 데이터를 변경하지 않는다.
- DynamoDB 테이블의 IAM, 인덱스, 실제 배포 환경변수까지 확인하는 검사는 배포 스모크 테스트에서 별도로 수행한다.
- 실제 HIVE 로그인 두 계정 E2E는 HIVE 인증 상태와 사람의 로그인이 필요하므로 이 툴의 범위가 아니다. 서버에는 이메일 대신 HIVE가 검증해 준 안정적인 `subject`만 저장 키로 사용한다.
