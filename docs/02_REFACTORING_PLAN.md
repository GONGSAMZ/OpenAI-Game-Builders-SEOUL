# 따끈따끈 붕어빵 리팩터링 계획

> **목표:** 게임 규칙과 화면은 유지하면서, 나중에 고치거나 기능을 더하기 쉬운 코드로 조금씩 정리한다.
>
> **원칙:** 한 번에 전부 바꾸지 않는다. 작은 작업 하나를 끝낼 때마다 하루 플레이가 정상인지 확인한다.

## 이번 작업에서 하지 않을 것

- 새로운 손님, 재료, 스테이지 추가
- 모든 스크립트를 한 번에 새 구조로 교체
- 현재 규모에 과한 구조(ECS, 의존성 주입 컨테이너 등) 도입
- 실제 문제가 확인되지 않은 성능 최적화

## 작업 순서

| 순서 | 작업 | 이유 | 우선순위 |
| --- | --- | --- | --- |
| 0 | 기준 플레이 목록 만들기 | 수정 뒤 문제가 생겼는지 확인하기 위해 | 필수 |
| 1 | 입력·주문 결과 오류 정리 | 플레이 중 오류와 이상한 결과를 막기 위해 | 가장 높음 |
| 2 | UI 이벤트 정리 | 날짜 전환 뒤 이전 화면 참조가 남지 않게 하기 위해 | 가장 높음 |
| 3 | 게임 관리 역할 나누기 | 한 파일이 너무 많은 일을 하지 않게 하기 위해 | 높음 |
| 4 | 밸런스 데이터 분리 | 가격과 재료를 쉽게 수정하기 위해 | 중간 |
| 5 | 리소스·프리팹 참조 안정화 | 이름 변경과 빌드 환경 차이의 오류를 줄이기 위해 | 중간 |
| 6 | 필요한 곳만 성능 개선 | 게임 규모가 커졌을 때를 대비하기 위해 | 나중 |

## 0. 시작 전: 기준 플레이

- [ ] 게임 시작부터 하루 종료까지 진행한다.
- [ ] 도구를 선택하지 않고 붕어빵을 클릭한다.
- [ ] 반죽, 재료, 굽기 순서로 붕어빵을 완성한다.
- [ ] 덜 익은 붕어빵과 탄 붕어빵을 전달한다.
- [ ] 주문과 다른 붕어빵을 전달한다.
- [ ] 손님을 오래 기다리게 한다.
- [ ] 5일차까지 진행해 엔딩을 확인한다.
- [ ] Unity Console에 빨간 오류가 없는지 확인한다.

**완료 기준:** 이후 모든 작업 뒤에도 위 행동을 다시 통과한다.

## 1. 입력과 주문 결과 안정화

### 1-1. 도구 미선택 클릭 처리

`FishBunController`에서 선택된 도구가 없는 상태로 붕어빵을 클릭하면 오류가 날 수 있다.

- [ ] 도구가 선택되었는지 먼저 확인한다.
- [ ] 선택되지 않았다면 조리를 진행하지 않는다.
- [ ] 필요하면 “도구를 먼저 선택하세요” 안내를 표시한다.

**대상:** `Assets/Scripts/Controllers/FishBunController.cs`  
**완료 기준:** 도구 없이 여러 번 클릭해도 Console 오류가 없다.

### 1-2. 잘못된 주문의 패널티 정리

현재 주문과 다른 붕어빵을 전달했을 때 화남 수치가 줄어드는 흐름이 있다. 의도한 규칙을 정한 뒤 수정한다.

- [ ] 잘못된 주문의 결과를 한 줄로 정한다. 예: 화남 20 증가.
- [ ] 화남 수치, 돈, 판매 수를 그 규칙에 맞게 수정한다.
- [ ] 성공/실패/탄 붕어빵/손님 이탈을 각각 확인한다.

**대상:** `Assets/Scripts/Controllers/CustomerController.cs`  
**완료 기준:** 화면 결과와 정한 게임 규칙이 일치한다.

### 1-3. 주문 결과를 한 곳에서 판단하기

- [ ] 주문 결과를 `Success`, `WrongOrder`, `Burned`, `Undercooked`처럼 한 번만 결정한다.
- [ ] 결과에 따른 돈, 화남 수치, 판매 수 처리를 한 흐름으로 모은다.
- [ ] 기존 메서드는 새 흐름이 안정된 뒤 정리한다.

**완료 기준:** 주문 결과를 수정할 곳이 여러 파일에 흩어져 있지 않다.

## 2. UI 이벤트 정리

`UI_Game`의 정적 이벤트는 화면이 닫힌 뒤에도 이전 UI 함수를 기억할 수 있다. 게임 상태가 알림을 보내고 UI가 받을 때만 연결되도록 바꾼다.

- [ ] 주문 변경 알림을 게임 관리 쪽에서 보낸다.
- [ ] UI는 `OnEnable`에서 연결하고 `OnDisable` 또는 `OnDestroy`에서 해제한다.
- [ ] 값이 바뀔 때만 돈·주문 UI를 갱신할 수 있는지 확인한다.
- [ ] 여러 날짜를 넘긴 뒤에도 UI 오류가 없는지 확인한다.

**대상:** `UI_Game.cs`, `GameManagerEx.cs`  
**완료 기준:** 날짜 전환 뒤에도 주문, 돈, 시간 UI가 정상이고 이전 UI 관련 오류가 없다.

## 3. 게임 관리 역할 나누기

`GameManagerEx`에는 날짜, 시간, 돈, 주문, 엔딩 판단이 함께 있다. 아래 순서로 하나씩 분리한다.

| 역할 | 담당 내용 |
| --- | --- |
| `GameSession` | 게임 시작, 하루 시작·종료, 날짜와 시간 |
| `OrderManager` | 주문 생성, 완료, 취소, 주문 결과 |
| `EconomyManager` | 보유 금액, 판매 수익, 재료 비용 |
| `EndingEvaluator` | 최종 금액과 날짜에 따른 엔딩 판단 |

- [ ] 첫 번째로 주문 관련 코드만 `OrderManager`로 옮긴다.
- [ ] 기존 `Managers.Game` 접근은 즉시 지우지 않고, 새 클래스에 전달하는 창구로 잠시 유지한다.
- [ ] 주문이 안정된 뒤 돈 계산, 엔딩 판단 순으로 하나씩 분리한다.

**완료 기준:** 주문·돈·엔딩을 수정할 때 각각의 담당 파일을 바로 찾을 수 있다.

## 4. 재료와 밸런스 데이터 분리

가격, 재료 이름, 엔딩 조건을 코드에 직접 적는 대신 Unity Inspector에서 바꿀 수 있는 데이터 파일로 옮긴다.

- [ ] `FillingData`: 표시 이름, 판매 가격, 원가, 아이콘
- [ ] `GameBalanceData`: 시작 금액, 하루 제한 시간, 엔딩 기준
- [ ] 기존 `Define` 값은 모든 참조가 옮겨진 뒤에만 정리한다.

**완료 기준:** 팥 붕어빵의 가격을 바꾸기 위해 C# 파일을 열 필요가 없다.

## 5. 리소스와 프리팹 참조 안정화

- [ ] `Resources.LoadAll`로 불러온 스프라이트 목록을 저장해 재사용한다.
- [ ] `SO` 폴더와 코드의 경로 대소문자를 정확히 맞춘다.
- [ ] 자식 오브젝트 이름을 문자열로 찾는 곳은 자주 수정하는 화면부터 `SerializeField` 참조로 바꾼다.
- [ ] UI를 닫을 때 비어 있는 팝업 목록을 닫으려는 경우를 안전하게 처리한다.

**대상 후보:** `ResourceManager.cs`, `UIManager.cs`, `Util.cs`, UI 스크립트

## 6. 성능 개선은 나중에

- [ ] 붕어빵 생성·삭제가 많아지면 오브젝트 풀을 검토한다.
- [ ] 값이 바뀌지 않은 UI의 매 프레임 갱신을 줄인다.
- [ ] 손님 화남 게이지 갱신 빈도를 조절한다.
- [ ] 붕어빵 상태가 바뀔 때마다 Collider를 제거·추가하는 방식을 검토한다.

**주의:** Profiler에서 실제 문제가 확인되기 전에는 이 작업을 먼저 하지 않는다.
