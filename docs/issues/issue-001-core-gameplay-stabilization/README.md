## 1. 이 문서의 목적

이슈 #1의 목표는 새 기능을 만드는 것이 아니라, 게임 시작부터 하루 정산까지의 기존 플레이가 멈추거나 잘못 계산되지 않게 만드는 것이다. 이 문서는 넓게 적힌 이슈 본문을 실제로 구현하고 확인할 수 있는 문제 단위로 나눈 작업 명세다.

## 2. 이슈 원문의 완료 조건

다음 흐름이 중단 없이 동작해야 한다.

```text
게임 시작
  → 주문 확인
  → 붕어빵 조리
  → 손님에게 전달
  → 판매 결과 반영
  → 영업 종료
  → 하루 정산
  → 다음 날 시작 또는 엔딩
```

추가로 다음 조건을 만족해야 한다.

- 진행을 막는 오류를 가장 먼저 수정한다.
- 돈, 판매 수량, 재료비, 손님 분노도, 주문 수량이 실제 행동과 일치해야 한다.
- 각 수정 항목의 재현 방법과 확인 결과를 이슈 댓글 또는 PR에 기록한다.
- 수정 뒤 핵심 흐름 전체를 다시 확인한다.

## 3. 조사 기준과 신뢰도

2026-08-16 기준 실제 Unity 프로젝트의 `Assets/Scripts/`를 정적으로 점검했다. “코드 확인”은 현재 코드에서 문제가 발생하는 경로를 찾았다는 뜻이며, “실행 확인 전”은 Unity Editor와 WebGL에서 같은 현상이 재현되는지 아직 검증해야 한다는 뜻이다.

기존 기록을 통해 WebGL 빌드 성공, 시작 화면 진입, 게임 장면 진입은 확인되어 있다. 주문부터 하루 종료까지의 전체 플레이 결과는 아직 증거가 없다.

## 5. 범위

### 포함

- 틀 생성과 조리 상태 전환
- 주문 접수, 제공 판정, 주문 취소

- 핵심 UI를 닫았다 다시 열었을 때의 상태 복원
- Unity Editor 및 WebGL 회귀 테스트

### 제외

- 신규 재료, 레시피, 손님, 스토리 추가

- 아트 전면 교체

PC 입력과 화면 배치 자체는 이슈 #4의 범위다. 다만 현재 입력에서 예외가 나거나 핵심 플레이가 멈추는 경우는 이슈 #1에서 고친다.

## 6. 구현 전 공통 원칙

### 6.1 한 행동은 한 번만 반영한다

붕어빵 한 개를 손님에게 전달했을 때 주문 수량, 진열 수량, 판매 수량, 매출은 각각 최대 한 번만 바뀌어야 한다. 같은 오브젝트를 다시 놓거나 잘못된 대상에게 놓았다고 값이 중복 변경되면 안 된다.

### 6.2 성공한 뒤 상태를 변경한다

도구나 대상이 올바른지 먼저 확인하고, 작업이 성공했을 때만 `isFilled`, 주문 수량, 진열 수량, 돈을 변경한다.

### 6.3 계산 기준값은 한 곳에만 둔다

시작 돈과 시작 날짜는 초기화할 때 한 번 복사한다. 값을 읽을 때마다 기준값을 더하지 않는다. 화면 표시와 정산도 같은 현재 데이터를 사용한다.

### 6.4 화면이 아니라 게임 상태를 기준으로 한다

UI를 닫았다 다시 만들어도 주문, 돈, 시간은 유지되어야 한다. UI는 현재 게임 상태를 다시 읽어 표시해야 한다.

## 7. 권장 작업 순서

1. 현재 코드로 회귀 테스트 계획의 `BASE` 항목을 실행하고 영상 또는 스크린샷, 콘솔 로그를 남긴다.
2. P0-01 틀 잠김 문제를 수정하고 단독 재현 테스트를 통과시킨다.
3. P0-02 전달 판정과 P1-03 진열 재고 상태를 하나의 흐름으로 정리한다.
4. P0-04 돈·날짜·정산의 기준값을 하나로 통합한다.
5. P1-05 손님 생성과 마감 상태를 정리한다.
6. P2-06 UI 복원과 빈 입력 안전성을 확인한다.
7. [전체 회귀 테스트](./verification/regression-test-plan.md)를 Editor와 WebGL에서 수행한다.
8. 재현 전·후 결과와 남은 문제를 이슈 또는 PR에 기록한다.

P0-02와 P1-03은 같은 드래그 한 번에 함께 바뀌는 데이터이므로 서로 다른 시점에 임시 수정을 반복하기보다 같은 브랜치에서 연속으로 처리하는 편이 안전하다.

## 8. 공통 완료 기준

- [ ] 시작 화면에서 게임 장면으로 진입할 수 있다.
- [ ] 주문을 받고 주문 수량을 확인할 수 있다.
- [ ] 올바른 도구 순서로 붕어빵을 만들 수 있다.
- [ ] 잘못된 도구나 잘못된 대상 조작이 진행을 막지 않는다.
- [ ] 만든 붕어빵을 진열하고 손님에게 전달할 수 있다.
- [ ] 성공한 판매만 주문·판매 수량·매출에 한 번 반영된다.
- [ ] 재료비가 실제 사용량과 일치한다.
- [ ] 영업 종료 후 손님이 모두 퇴장하면 하루 정산 화면으로 이동한다.
- [ ] 정산의 매출, 재료비, 순이익과 최종 보유금이 수기로 계산한 값과 같다.
- [ ] 다음 날 시작 때 이전 날의 임시 오브젝트와 주문이 남지 않는다.
- [ ] 브라우저 콘솔에 핵심 플레이 관련 예외가 없다.
- [ ] 회귀 테스트 결과와 증거 링크가 PR 또는 이슈에 남아 있다.
