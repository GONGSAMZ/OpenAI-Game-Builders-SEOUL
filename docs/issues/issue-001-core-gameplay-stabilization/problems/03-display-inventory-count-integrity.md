# P1-03 — 진열대 수량이 중복 증가하거나 음수가 되는 문제

## 한 줄 설명

현재 코드는 붕어빵이 실제로 진열대에 있었는지 확인하지 않고 수량을 더하거나 뺀다. 같은 붕어빵을 다시 진열하면 중복 증가하고, 틀에서 손님에게 바로 전달하면 수량이 음수가 될 수 있다.

## 현재 상태

- 코드 확인: 완료
- Unity Editor 재현: 필요
- WebGL 재현: 필요
- 우선순위: `P1`
- 주요 파일: `Assets/Scripts/Controllers/DisplateController.cs`, `Assets/Scripts/Controllers/FishBunController.cs`

> 코드의 `DisplateController` 철자는 기존 이름을 그대로 적은 것이다. 이번 안정화 작업에서 파일·클래스 이름을 바꾸면 씬과 참조에 영향을 줄 수 있으므로, 별도 필요가 없다면 이름 변경은 하지 않는다.

## 재현 시나리오

### 시나리오 A — 틀에서 손님에게 바로 전달

1. 붕어빵을 완성한다.
2. 진열대를 거치지 않고 손님에게 바로 드래그한다.
3. 같은 맛의 다음 붕어빵을 진열대에 놓는다.

현재 코드에서는 2단계에서 수량이 `0 → -1`이 되고, 3단계의 위치와 정렬 순서가 음수 기준으로 계산될 수 있다.

### 시나리오 B — 같은 붕어빵 재진열

1. 완성한 붕어빵을 진열대에 놓는다.
2. 같은 붕어빵을 들어 같은 진열대에 다시 놓는다.
3. 이 동작을 반복한다.

실제 오브젝트는 한 개인데 수량은 매번 증가할 수 있다.

### 시나리오 C — 진열품을 쓰레기통에 버림

1. 붕어빵을 진열한다.
2. 진열된 붕어빵을 쓰레기통에 버린다.
3. 같은 맛을 다시 진열한다.

현재 진열 수량이 감소하지 않으면 새 오브젝트의 위치가 빈 공간을 남기거나 최대 수량 판정이 틀어질 수 있다.

## 원인

- `DisplateController.Set()`은 호출될 때마다 수량을 증가시킨다.
- `DisplateController.Reset()`은 현재 수량과 오브젝트의 진열 여부를 확인하지 않고 감소시킨다.
- `FishBunController`에는 “현재 진열 중인지”를 나타내는 상태가 없다.
- 선언된 `maxAllowedFishBun`이 실제 입고 검사에 사용되지 않는다.

## 수정 방향

### 최소 수정안

각 붕어빵에 `isOnDisplay` 상태를 둔다.

- 처음 진열 성공: `false → true`, 해당 맛 수량 `+1`
- 이미 진열 중인 오브젝트 재배치: 수량 변화 없음
- 진열품 판매·폐기: `true → false`, 해당 맛 수량 `-1`
- 틀에서 직접 판매·폐기: 수량 변화 없음

### 권장 수정안

진열대가 맛별 오브젝트 목록을 직접 관리하고 `TryAdd`, `TryRemove`를 제공한다. 단순 숫자만 저장하는 것보다 실제 오브젝트와 수량이 어긋날 가능성이 작다.

```text
실제 진열 오브젝트 수 == 화면 배치에 사용하는 수량 == 판매·폐기 시 감소하는 수량
```

최대 수량 5개를 유지할 계획이라면 `TryAdd`가 가득 찬 상태를 실패로 반환해야 한다. 최대 수량 기능을 쓰지 않을 계획이면 이번 이슈에서 사용하지 않는 상수를 제거하거나 후속 작업으로 명시한다.

## 위치 재정렬 정책

중간 오브젝트를 판매하거나 폐기한 뒤 남은 오브젝트를 다시 촘촘하게 배치하는 것이 가장 명확하다. 일정상 재정렬까지 하기 어렵다면 최소한 다음 입고 위치와 정렬 순서가 음수 또는 중복이 되지 않아야 한다.

## 완료 조건

- [ ] 틀에서 손님에게 바로 전달해도 진열 수량은 0보다 작아지지 않는다.
- [ ] 같은 붕어빵을 다시 진열해도 수량이 늘지 않는다.
- [ ] 진열품 판매 시 해당 맛 수량이 정확히 1 감소한다.
- [ ] 진열품 폐기 시 해당 맛 수량이 정확히 1 감소한다.
- [ ] 진열하지 않은 붕어빵 판매·폐기는 수량을 변경하지 않는다.
- [ ] 다음 날 시작 시 모든 맛의 진열 수량이 0이다.
- [ ] 반복 입고·출고 뒤에도 위치와 앞뒤 정렬이 정상이다.
