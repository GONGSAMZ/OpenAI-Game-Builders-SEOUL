# P0-04 — 돈·날짜·하루 정산 계산이 같은 기준을 사용하지 않는 문제

## 한 줄 설명

현재 돈과 날짜는 값을 읽을 때 시작값을 매번 더하는 구조다. `Money += 판매금액` 같은 코드에서는 읽기와 쓰기가 연속으로 일어나 시작 돈이 다시 누적될 수 있다. 날짜도 같은 구조라 첫날 표시와 엔딩 시점이 의도와 다를 수 있다.

## 코드에서 확인한 계산 구조

- `Managers`에는 시작 돈 `5000`, 기준 날짜 `3`이 있다.
- `GameManagerEx.Money` 읽기는 현재 데이터에 시작 돈을 더한다.
- `Money` 쓰기는 전달된 전체 값을 현재 데이터에 저장한다.
- 따라서 `Money += pay`는 이미 시작 돈이 포함된 값을 읽은 뒤 저장하고, 다음 읽기에서 시작 돈을 또 더할 수 있다.
- `Day`도 현재 날짜와 기준 날짜를 읽을 때 더한다.
- 하루 시작 때 내부 날짜가 증가하므로 첫날부터 `Day 4`처럼 표시될 가능성이 있다.
- `yesterdayProfit`은 내부 돈을 사용하고 `todayRevenue`는 시작 돈이 포함된 `Money`를 사용해 계산 기준이 다르다.

## 재현 절차

### 돈 누적

1. 게임 시작 직후 화면의 돈을 기록한다.
2. 가격이 알려진 붕어빵 한 개를 정상 판매한다.
3. 손님 퇴장 후 화면의 돈을 기록한다.
4. 같은 가격의 붕어빵을 한 개 더 판매한다.
5. 시작 돈 + 판매금액 합과 화면 값을 비교한다.

### 날짜와 엔딩

1. 첫 영업일의 날짜 표시를 기록한다.
2. 하루 종료와 다음 날 시작을 반복한다.
3. 내부 설정의 엔딩 날짜와 실제 엔딩이 나타난 날짜를 비교한다.

### 하루 정산

1. 한 가지 맛만 사용해 판매 수량과 가격을 통제한다.
2. 사용한 반죽과 속 재료 횟수를 기록한다.
3. 정산의 매출, 재료비, 순이익, 최종 보유금을 직접 계산한 값과 비교한다.

## 수정 방향

### 1. 시작값과 현재값을 분리한다

시작 돈과 시작 날짜는 읽기용 설정값으로 두고, 게임 초기화 시 현재 데이터에 한 번만 복사한다.

```text
초기화: currentMoney = startingMoney
조회:   currentMoney 그대로 반환
판매:   currentMoney += acceptedSalePrice
```

날짜도 같은 방식으로 현재 날짜 자체를 저장하고, 하루 시작 때 정확히 한 번만 증가시킨다. 시작 날짜가 1인지 3인지는 게임 기획값이므로 구현 전에 팀이 확정하되, 어떤 값이든 중복 가산되면 안 된다.

### 2. 하루 장부를 명시적으로 관리한다

권장 계산식은 다음과 같다.

```text
오늘 매출 = 성공한 판매 가격의 합
오늘 재료비 = 실제 생성·투입에 성공한 재료 비용의 합
오늘 순이익 = 오늘 매출 - 오늘 재료비
마감 후 보유금 = 마감 전 보유금 - 아직 차감하지 않은 재료비
```

재료비를 사용 즉시 보유금에서 뺄지, 마감에 한 번 뺄지는 둘 중 하나만 선택한다. 현재 구조처럼 통계에는 누적하고 마감에 차감한다면 마감 함수가 두 번 호출되어도 중복 차감되지 않아야 한다.

### 3. 판매 성공과 매출 반영을 연결한다

매출과 판매 수량은 [P0-02 전달 성공](./02-serving-transaction-integrity.md)이 확정된 경우에만 증가시킨다. 손님이 받지 않은 붕어빵은 매출에 포함하지 않는다.

### 4. 화면은 계산하지 않고 결과만 표시한다

`UI_DayEnd`는 장부 값을 읽어 표시만 한다. UI 생성 시점에 오래된 값을 보관하지 않도록 `Init()`에서 최신 값을 구성한다.

## 기준 숫자 테스트

시작 돈을 `5,000원`, 팥 붕어빵 가격을 `500원`, 반죽 비용을 `100원`, 팥 속 비용을 `100원(500 × 0.2)`으로 가정한다.

붕어빵 한 개를 만들어 정상 판매했을 때:

| 항목 | 기대값 |
|---|---:|
| 판매 수량 | 1개 |
| 오늘 매출 | 500원 |
| 재료비 | 200원 |
| 오늘 순이익 | 300원 |
| 마감 후 보유금 | 5,300원 |

같은 조건에서 두 개를 만들어 하나만 판매하고 하나를 폐기하면:

| 항목 | 기대값 |
|---|---:|
| 판매 수량 | 1개 |
| 오늘 매출 | 500원 |
| 재료비 | 400원 |
| 오늘 순이익 | 100원 |
| 마감 후 보유금 | 5,100원 |

## 완료 조건

- [ ] 게임 시작 시 설정한 시작 돈이 정확히 한 번만 적용된다.
- [ ] 판매 한 번마다 해당 가격만 증가한다.
- [ ] 판매하지 않은 붕어빵은 매출과 판매 수량에 포함되지 않는다.
- [ ] 재료비는 성공한 재료 사용 횟수와 일치한다.
- [ ] 하루 정산 다섯 항목이 직접 계산한 값과 같다.
- [ ] 마감 처리가 중복 호출되어도 재료비가 두 번 빠지지 않는다.
- [ ] 날짜는 하루마다 정확히 1 증가한다.
- [ ] 엔딩 검사는 기획에서 정한 날짜에 한 번 실행된다.
- [ ] 다음 날의 매출·재료비·판매 수량은 0에서 다시 시작한다.
