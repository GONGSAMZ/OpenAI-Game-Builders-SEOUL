# P0-01 — 잘못된 도구 선택 시 빈 조리 틀이 잠기는 문제

## 한 줄 설명

빈 조리 틀에 반죽 주전자가 아닌 도구를 사용하면 붕어빵은 생성되지 않지만, 틀은 이미 찬 것으로 기록될 수 있다. 이후 올바른 도구를 사용해도 그 틀에서 조리를 시작할 수 없게 된다.

## 현재 상태

- 코드 확인: 완료
- Unity Editor 재현: 필요
- WebGL 재현: 필요
- 우선순위: `P0`
- 주요 파일: `Assets/Scripts/Controllers/MoldController.cs`, `Assets/Scripts/Util.cs`

## 재현 절차

1. 게임 장면에 진입한다.
2. 반죽 주전자가 아닌 속 재료 도구를 선택한다.
3. 비어 있는 조리 틀을 한 번 누른다.
4. 반죽 주전자를 선택한다.
5. 같은 조리 틀을 다시 누른다.

## 예상 결과

- 3단계에서는 아무것도 생성되지 않고 틀은 계속 빈 상태여야 한다.
- 5단계에서는 붕어빵 반죽이 정상 생성되어야 한다.
- 재료비는 실제 반죽이 생성된 한 번만 증가해야 한다.

## 현재 코드에서 예상되는 결과

`MoldController.OnPointerClick()`은 선택 도구가 존재하기만 하면 `ExecuteOnce()`를 호출한다. 실제 생성 함수는 주전자 태그일 때만 붕어빵을 만들지만, `ExecuteOnce()`는 생성 성공 여부와 관계없이 `isFilled` 값을 뒤집는다. 따라서 잘못된 도구를 사용한 뒤 틀이 찬 상태로 남을 수 있다.

## 원인

검증과 상태 변경의 순서가 반대다.

```text
현재: 1회 실행 상태 변경 → 생성 함수 안에서 도구 검사 → 생성하지 않음
권장: 도구와 빈 틀 검사 → 생성 성공 → 찬 상태로 변경
```

## 수정 방향

1. `OnPointerClick()` 시작 부분에서 선택한 도구가 주전자인지 확인한다.
2. 틀이 이미 차 있으면 즉시 반환한다.
3. 붕어빵 생성이 성공한 뒤에만 `IsFilled = true`로 바꾼다.
4. 가능하면 생성 함수를 `bool TryInstantiateFishBun()` 형태로 바꿔 성공 여부를 호출자에게 돌려준다.
5. 재료비도 생성 성공 뒤 같은 위치에서 한 번만 더한다.

`ExecuteOnce()`는 여러 곳에서 사용하므로, 이 문제만 해결하려고 공용 함수의 의미를 크게 바꾸지 않는다. 틀 생성 로직에서 명시적으로 검증하는 편이 영향 범위가 작다.

## 변경 시 지켜야 할 상태 규칙

- 빈 틀 + 주전자: 붕어빵 1개 생성, `IsFilled = true`, 반죽 비용 1회 증가
- 빈 틀 + 다른 도구: 변화 없음
- 찬 틀 + 어떤 도구: 새 붕어빵 생성 없음, 비용 변화 없음
- 붕어빵을 유효한 곳으로 옮김: 원래 틀 `IsFilled = false`
- 다음 날 시작: 모든 틀 `IsFilled = false`

## 완료 조건

- [ ] 잘못된 도구로 빈 틀을 5회 눌러도 틀이 잠기지 않는다.
- [ ] 이후 주전자로 누르면 붕어빵이 정확히 1개 생성된다.
- [ ] 이미 찬 틀을 반복 클릭해도 오브젝트와 비용이 늘지 않는다.
- [ ] 진열대·손님·쓰레기통으로 옮긴 뒤 같은 틀을 다시 사용할 수 있다.
- [ ] 다음 날 시작 뒤 모든 틀을 다시 사용할 수 있다.
- [ ] 콘솔에 `NullReferenceException` 또는 중복 생성 예외가 없다.
