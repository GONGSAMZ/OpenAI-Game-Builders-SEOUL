# P0-02 — 전달 판정과 주문·판매 결과가 한 번에 일치하지 않는 문제

## 한 줄 설명

붕어빵을 손님 쪽으로 옮기면 손님이 주문을 받지 않았거나 맛이 틀려도 붕어빵이 사라질 수 있다. 이때 판매 수량, 주문 수량, 분노도, 진열 수량 중 일부만 바뀌어 결과가 서로 맞지 않을 수 있다.

## 현재 상태

- 코드 확인: 완료
- Unity Editor 재현: 필요
- WebGL 재현: 필요
- 우선순위: `P0`
- 주요 파일: `Assets/Scripts/Controllers/FishBunController.cs`, `Assets/Scripts/Controllers/CustomerController.cs`, `Assets/Scripts/Managers/GameManagerEx.cs`

## 재현 시나리오

### 시나리오 A — 주문을 받기 전 전달

1. 손님을 누르지 않아 주문을 접수하지 않는다.
2. 완성한 붕어빵을 손님에게 드래그한다.

### 시나리오 B — 주문과 다른 맛 전달

1. 손님의 주문을 접수한다.
2. 주문에 없는 맛의 붕어빵을 전달한다.

### 시나리오 C — 올바른 맛 전달

1. 손님의 주문을 접수한다.
2. 주문에 있는 맛을 한 개 전달한다.

## 예상 결과

| 시나리오 | 붕어빵 | 주문 수량 | 판매 수량 | 매출 | 분노도 |
|---|---|---|---|---|---|
| A | 원래 위치로 복귀 | 변화 없음 | 변화 없음 | 변화 없음 | 정책에 따른 변화 또는 없음 |
| B | 정한 정책대로 복귀 또는 폐기 | 변화 없음 | 변화 없음 | 변화 없음 | 증가 |
| C | 제거 | 1 감소 | 1 증가 | 가격만큼 증가 | 품질에 따라 감소 |

잘못 전달한 붕어빵을 돌려줄지 폐기할지는 구현 전에 한 번 결정해야 한다. 가장 작은 안정화 수정은 “거부된 전달은 원래 위치로 복귀”다. 어느 정책을 선택해도 모든 데이터는 같은 결과를 반영해야 한다.

## 현재 코드에서 확인한 위험

1. `FishBunController.OnEndDrag()`는 손님 충돌 뒤 전달 성공 여부를 받지 않고 오브젝트를 파괴한다.
2. `CustomerController.Eat()`는 주문을 받지 않았으면 바로 반환하지만, 호출자는 그 실패를 알 수 없다.
3. 주문과 다른 맛을 주면 `orderAngryPoint`를 더하지 않고 빼고 있어, 잘못된 제공이 오히려 분노도를 낮출 수 있다.
4. `totalFishBunsSold`는 성공 여부와 관계없이 `Eat()` 끝에서 증가할 수 있다.
5. 전역 주문과 손님별 주문을 서로 다른 함수에서 따로 감소시켜, 한쪽만 바뀌는 경로가 생기기 쉽다.

## 수정 방향

### 1. 전달 결과를 명시한다

`CustomerController`가 다음과 같은 결과를 반환하도록 만든다.

```csharp
enum ServeResult
{
    Accepted,
    OrderNotAccepted,
    WrongFilling,
    CustomerLeaving
}
```

정확한 이름은 구현 시 프로젝트 규칙에 맞춰 바꿀 수 있다. 중요한 점은 `FishBunController`가 성공 여부를 알아야 한다는 것이다.

### 2. 성공한 판매를 하나의 작업으로 처리한다

`Accepted`일 때만 다음 값을 함께 변경한다.

- 손님별 남은 주문 수량 1 감소
- 전체 주문 표시 수량 1 감소
- 판매 수량 1 증가
- 손님이 지불할 금액 증가
- 진열 중이었던 붕어빵이면 진열 수량 1 감소
- 붕어빵 오브젝트 제거

중간에 실패하면 어느 값도 일부만 바뀌지 않아야 한다.

### 3. 실패한 전달 정책을 한 곳에서 처리한다

- 주문 미접수: 원래 위치로 복귀
- 잘못된 맛: 원래 위치로 복귀하고 분노도 증가
- 퇴장 중인 손님: 원래 위치로 복귀

### 4. 판매 수량의 의미를 고정한다

`totalFishBunsSold`는 손님이 실제로 받아 돈 계산 대상이 된 붕어빵만 센다. 쓰레기통에 버리거나 거부된 붕어빵은 판매 수량이 아니다.

## 완료 조건

- [ ] 주문 미접수 손님에게 전달해도 주문·매출·판매 수량이 변하지 않는다.
- [ ] 주문과 다른 맛을 전달해도 주문 수량이 줄지 않는다.
- [ ] 잘못된 맛 제공이 분노도를 낮추지 않는다.
- [ ] 올바른 맛 한 개는 손님 주문과 전체 주문에서 각각 정확히 한 개만 감소한다.
- [ ] 성공한 판매만 판매 수량과 지불 금액에 한 번 반영된다.
- [ ] 주문 마지막 한 개를 전달하면 손님이 한 번만 퇴장한다.
- [ ] 연속 드래그나 중복 이벤트로 같은 붕어빵이 두 번 판매되지 않는다.

## 단독 테스트

| 테스트 | 조건 | 기대값 |
|---|---|---|
| SERVE-01 | 주문 미접수 + 직접 전달 | 모든 주문·판매 값 유지, 오브젝트 복귀 |
| SERVE-02 | 주문 접수 + 틀린 맛 | 주문 유지, 판매 0, 매출 0, 분노 증가 |
| SERVE-03 | 주문 접수 + 맞는 맛 1개 | 주문 1 감소, 판매 1, 가격 1회 적립 |
| SERVE-04 | 마지막 주문 전달 | 손님 퇴장 1회, 남은 주문 0 |
| SERVE-05 | 같은 오브젝트로 빠른 드래그 반복 | 최대 1회만 반영 |
