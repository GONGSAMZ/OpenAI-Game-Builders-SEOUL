# P1-05 — 손님 생성·대기·퇴장과 영업 마감 상태가 엇갈리는 문제

## 한 줄 설명

손님은 화면에 나타나기 전부터 현재 손님 수와 대기 시간이 계산된다. 생성 대기 중 마감 시간이 되어도 나중에 손님이 나타날 수 있어 하루 종료가 예상보다 늦어지거나 보이지 않는 손님 때문에 종료 조건이 맞지 않을 수 있다.

## 현재 상태

- 코드 확인: 완료
- Unity Editor 재현: 필요
- WebGL 재현: 필요
- 우선순위: `P1`
- 주요 파일: `Assets/Scripts/Controllers/CustomerController.cs`, `Assets/Scripts/Managers/GameManagerEx.cs`

## 현재 코드 흐름

```text
다음 손님 코루틴 시작
  → 마감 여부 1회 확인
  → 손님 데이터 초기화
  → 현재 손님 수 +1
  → 대기 시간 측정 시작
  → 3~8초 생성 대기
  → 손님 화면 표시
```

마감 검사가 대기 전에 한 번만 실행되므로, 대기 중 마감 시간이 되면 마감 뒤 손님이 화면에 나타날 수 있다. 또한 보이지 않는 대기 시간도 분노도에 포함된다.

## 재현 절차

### 시나리오 A — 생성 대기 중 마감

1. 마감 직전에 기존 손님을 퇴장시켜 다음 손님 생성 코루틴을 시작한다.
2. 새 손님의 3~8초 대기 중 마감 시간이 되도록 한다.
3. 마감 뒤 새 손님이 나타나는지 확인한다.
4. 현재 손님 수가 0이 되어 정산 화면으로 가는 시점을 확인한다.

### 시나리오 B — 보이지 않는 시간의 분노도

1. 새 손님 생성이 예약되는 순간의 게임 시간을 기록한다.
2. 화면에 나타나는 순간의 분노 게이지를 확인한다.
3. 생성 지연 시간이 이미 분노에 포함되었는지 확인한다.

### 시나리오 C — 화난 손님의 주문 취소

1. 주문을 접수한 뒤 일부만 제공한다.
2. 손님이 화나서 퇴장할 때까지 기다린다.
3. 전체 주문 표시에서 남은 주문이 모두 제거되는지 확인한다.
4. 현재 손님 수가 정확히 한 번 감소하는지 확인한다.

## 추가 위험

- `cancelOrder()`는 한 맛의 전역 주문을 찾지 못하면 바로 반환해 뒤에 남은 다른 맛 주문을 취소하지 않을 수 있다.
- 현재 손님 수는 화면에 실제로 활성화된 손님이 아니라 생성 예약 중인 손님도 포함할 수 있다.
- 설정 화면에서 `isRunning`을 꺼도 `WaitForSeconds` 기반 생성·퇴장 코루틴은 계속 진행될 수 있다.
- 여러 종료 경로가 겹치면 현재 손님 수가 두 번 감소하지 않는지 확인이 필요하다.

## 수정 방향

### 1. 생성 대기와 활성 손님을 구분한다

권장 순서는 다음과 같다.

```text
생성 대기
  → 마감·일시정지·씬 유효성 재확인
  → 손님 초기화
  → 화면 활성화
  → 현재 손님 수 +1
  → 대기 시간 측정 시작
```

마감이 시작되면 예약된 새 손님은 취소한다. `isAllExited`는 실제 활성 손님과 퇴장 반응 중인 손님만 기준으로 판단한다.

### 2. 손님 상태를 명확히 둔다

불리언 여러 개가 겹치지 않도록 최소한 다음 상태를 구분한다.

- `WaitingToSpawn`
- `WaitingForOrder`
- `Serving`
- `Leaving`
- `Inactive`

반드시 열거형을 새로 만들 필요는 없지만, 한 손님이 동시에 두 번 퇴장하거나 퇴장 중 음식을 받는 경로는 막아야 한다.

### 3. 주문 취소를 끝까지 처리한다

손님별 남은 주문을 순회하면서 전역 주문에 해당 맛이 없더라도 다른 맛 처리를 계속한다. 값은 0 미만이 되지 않게 하고 0이면 키를 제거한다. 마지막에 주문 UI 갱신을 한 번 호출한다.

### 4. 일시정지 정책을 통일한다

`isRunning == false`일 때 게임 시간뿐 아니라 손님 생성·퇴장 대기까지 멈출지 결정한다. 설정 화면이 실제 일시정지라면 코루틴도 같은 상태를 따라야 한다.

## 완료 조건

- [ ] 마감 뒤 새 손님이 나타나지 않는다.
- [ ] 화면에 나타나지 않은 예약 손님이 현재 손님 수에 포함되지 않는다.
- [ ] 손님 분노도는 화면에 나타난 뒤부터 증가한다.
- [ ] 화난 손님 퇴장 시 남은 전역 주문이 모두 취소된다.
- [ ] 손님 한 명당 현재 손님 수는 활성화 때 1회 증가, 퇴장 때 1회 감소한다.
- [ ] 모든 손님이 나가면 정산 화면으로 정확히 한 번 이동한다.
- [ ] 퇴장 중인 손님에게 붕어빵을 전달해도 상태가 바뀌지 않는다.
- [ ] 설정 화면의 일시정지 정책과 생성·퇴장 타이머 동작이 일치한다.
