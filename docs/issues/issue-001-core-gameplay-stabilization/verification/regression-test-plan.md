# Issue #1 회귀 테스트 계획

## 1. 목적

개별 버그를 고친 뒤 시작부터 하루 종료까지 기존 기능이 다시 망가지지 않았는지 확인한다. “회귀 테스트”는 수정한 기능뿐 아니라 그 주변의 원래 기능도 다시 실행해 보는 검사다.

## 2. 테스트 환경

최소 두 환경에서 확인한다.

| 환경 | 목적 | 필수 여부 |
|---|---|---|
| Unity Editor Play Mode | 빠른 재현, Inspector와 콘솔 확인 | 필수 |
| WebGL 로컬 빌드 + 목표 PC 브라우저 | 실제 공개 환경의 입력·코루틴·화면 전환 확인 | 필수 |

기록할 정보:

- Unity 버전
- Git 커밋 또는 작업 브랜치
- 운영체제
- 브라우저 이름과 버전
- WebGL 빌드 시각
- 테스트 담당자와 날짜

## 3. 테스트 데이터 고정

돈 계산은 무작위 주문과 분리해 확인할 수 있도록 다음 값을 기록한다.

- 시작 돈
- 시작 날짜
- 선택한 맛과 판매 가격
- 반죽 비용
- 속 재료 비용 비율
- 만든 개수, 판매 개수, 폐기 개수

무작위 주문 때문에 같은 조건을 만들기 어렵다면 개발용 고정 주문을 일시적으로 사용할 수 있다. 이 코드는 배포 빌드에 남기지 않거나 명확한 개발 플래그로 제한한다.

## 4. 수정 전 기준 테스트

수정 전에 아래 항목을 한 번 실행해 실제로 재현되는 문제만 증거를 남긴다.

| ID | 항목 | 결과 | 증거 |
|---|---|---|---|
| BASE-01 | 시작 화면 → 게임 장면 진입 | 미실행 | |
| BASE-02 | 잘못된 도구 뒤 틀 잠김 | 미실행 | |
| BASE-03 | 주문 전 또는 틀린 맛 전달 | 미실행 | |
| BASE-04 | 직접 전달 뒤 진열 수량 이상 | 미실행 | |
| BASE-05 | 연속 판매 뒤 돈 증가 이상 | 미실행 | |
| BASE-06 | 생성 대기 중 마감 | 미실행 | |
| BASE-07 | 설정 화면 복귀 뒤 주문 UI | 미실행 | |

재현되지 않은 항목은 삭제하지 말고 환경, 조작, 결과를 적는다. 코드 수정이 이미 적용됐거나 씬 설정이 달라 재현되지 않을 수 있기 때문이다.

## 5. 핵심 흐름 테스트

### FLOW-01 — 게임 시작

1. 빌드를 새로 실행한다.
2. 시작 화면을 누른다.
3. 조작 안내 화면을 확인하고 게임 장면으로 이동한다.

통과 조건:

- 게임 장면과 HUD가 표시된다.
- 날짜와 시작 돈이 기획값과 같다.
- 콘솔 오류가 없다.

### FLOW-02 — 주문 접수

1. 손님이 나타날 때까지 기다린다.
2. 손님의 초기 분노 게이지를 확인한다.
3. 손님을 한 번 눌러 주문을 받는다.
4. 같은 손님을 다시 누른다.

통과 조건:

- 손님은 보이기 시작할 때 현재 손님 수에 포함된다.
- 주문 수량은 허용 범위 안이며 총합과 화면 표시가 같다.
- 두 번째 클릭으로 같은 주문이 중복 추가되지 않는다.

### FLOW-03 — 정상 조리

1. 주전자를 선택해 빈 틀에 반죽을 만든다.
2. 주문에 맞는 속 재료를 선택해 넣는다.
3. 주전자를 선택해 윗반죽을 넣는다.
4. 정해진 굽기 시간 뒤 각 조리 단계를 진행한다.
5. 완성품을 진열한다.

통과 조건:

- 단계가 한 단계씩만 진행된다.
- 잘못된 도구는 상태와 비용을 바꾸지 않는다.
- 반죽과 속 재료 비용이 각각 한 번 반영된다.
- 완성 전에는 드래그되지 않는다.
- 진열 수량은 1이다.

### FLOW-04 — 정상 판매

1. 주문과 맞는 완성품을 손님에게 전달한다.
2. 남은 주문, 진열 수량, 판매 수량, 돈을 기록한다.
3. 주문이 끝날 때까지 반복한다.

통과 조건:

- 한 개 전달마다 주문과 진열 수량이 각각 1 감소한다.
- 판매 수량과 지불 예정 금액은 각각 1회 증가한다.
- 마지막 제품 뒤 손님이 한 번 퇴장한다.
- 손님 퇴장 뒤 지불 금액이 정확히 한 번 보유금에 반영된다.

### FLOW-05 — 영업 종료와 정산

1. 마감 시간까지 플레이한다.
2. 진행 중 손님이 있으면 주문 완료 또는 분노 퇴장까지 기다린다.
3. 하루 정산 화면의 다섯 값을 기록한다.

통과 조건:

- 마감 뒤 새 손님이 나타나지 않는다.
- 모든 손님 퇴장 뒤 정산 화면이 한 번 나타난다.
- 판매 수량, 손님 수, 매출, 재료비, 순이익이 기록과 같다.
- 최종 보유금이 직접 계산한 값과 같다.

### FLOW-06 — 다음 날

1. 정산 화면에서 확인을 누른다.
2. 상점에서 다음 날 버튼을 누른다.
3. 새 영업일 상태를 확인한다.

통과 조건:

- 날짜가 1 증가한다.
- 보유금과 영구 진행 데이터는 유지된다.
- 주문, 일일 통계, 틀, 진열 수량은 초기화된다.
- 손님 생성은 한 주기만 시작한다.

## 8. 반복 안정성 테스트

다음 과정을 최소 3일 연속 반복한다.

1. 주문 2건 이상 접수
2. 붕어빵 3개 이상 제작
3. 정상 판매와 폐기 각각 1회 이상 수행
4. 설정 화면 왕복 1회
5. 마감과 정산
6. 다음 날 시작

통과 조건:

- 날짜가 하루에 1씩 증가한다.
- 돈이 이전 날 최종값에서 이어진다.
- 일일 통계와 임시 오브젝트만 초기화된다.
- 진열 수량이 음수가 되거나 실제 오브젝트 수와 달라지지 않는다.
- 현재 손님 수가 마감 후 0이다.
- 콘솔 예외가 없다.

## 9. 자동 테스트 권장 범위

현재 프로젝트에서 테스트 코드는 확인되지 않았다. 이번 수정에서 계산과 상태 변경을 Unity 오브젝트에서 분리할 수 있다면 다음 최소 자동 테스트를 추가한다.

- Edit Mode: 시작 돈 초기화와 판매 누적
- Edit Mode: 매출·재료비·순이익 계산
- Edit Mode: 주문 한 개 제공과 잘못된 맛 거부
- Edit Mode: 전역 주문 취소가 모든 맛을 처리하는지 확인
- Edit Mode: 진열 `TryAdd`·`TryRemove`의 중복과 음수 방지
- Play Mode: 잘못된 도구 뒤 틀 재사용
- Play Mode: 마감 중 예약 손님 미생성

자동 테스트 도입이 일정상 어렵더라도, 위 수치 테스트는 수동으로 실행하고 결과를 남겨야 한다.

## 11. 출시 차단 기준

다음 중 하나라도 해당하면 이슈 #1을 완료 처리하지 않는다.

- 시작부터 정산까지 흐름을 끝낼 수 없음
- 틀이 영구적으로 잠기거나 조리 상태가 진행되지 않음
- 주문 수량이 음수가 되거나 실제 주문과 다름
- 진열 수량이 음수 또는 실제 오브젝트 수와 다름
- 판매·돈·재료비가 한 행동에 두 번 이상 반영됨
- 마감 후 손님이 새로 나타나거나 정산 화면으로 가지 못함
- 핵심 흐름 중 처리되지 않은 콘솔 예외 발생
