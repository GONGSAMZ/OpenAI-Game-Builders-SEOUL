# 손님 8명 이야기와 붕어빵 영혼 콘텐츠 기획

## 1. 작업 목표

기존 붕어빵 타이쿤의 손님 콘텐츠를 확장해, 하루 영업이 끝날 때 손님의 사연을 읽고 그 사람에게 필요한 성격의 붕어빵 영혼을 만들어 주는 특별 주문 시스템을 문서로 구체화한다.

최종 기획 범위는 다음과 같다.

- 손님 8명이 서로 다른 성격, 연령, 생활 영역과 고민을 가진다.
- 맛과 굽기 상태의 조합에 따라 붕어빵 영혼의 성격이 달라진다.
- 손님에게 필요한 영혼은 손님과 단순히 무작위로 반대되는 존재가 아니라, 현재 부족한 태도를 보완하는 존재다.
- 5일차 엔딩을 제거하고 하나의 저장 데이터에서 영업일이 계속 이어지는 무한 운영을 전제로 한다.
- 손님 이야기와 붕어빵 영혼 도감을 장기 수집 목표로 사용한다.
- 낮 영업 중 손님을 클릭해 말동무가 되고, 선택형 대화로 특별 주문의 단서를 알아내는 흐름을 포함한다.

## 2. Codex에 준 맥락과 요청

- 기존 게임에는 정현, 하영, 미주 3명의 손님과 팥, 슈크림, 초코, 크림치즈, 피자, 민트, 고구마, 녹차의 8가지 속재료가 구현돼 있었다.
- 사용자는 각 손님에게 사연이 있고, 하루 마지막에 특정 손님이 특별 주문을 하는 콘텐츠를 제안했다.
- 특별 손님은 고민을 암시하는 짧은 대사만 말하고 붕어빵 하나를 주문한다.
- 붕어빵은 완벽하게 구운 상태만 정답인 것이 아니라, 맛과 굽기 상태에 따라 서로 다른 영혼을 가진다.
- 손님의 이야기와 반대되는 성격의 영혼을 정확히 건네면 이야기 컷과 도감이 해금돼야 한다.
- 처음에는 적은 수의 손님으로 범위를 잡는 안도 논의했으나, 사용자가 최종적으로 손님 수를 8명으로 결정했다.
- 사용자는 기존 5일 종료를 없애고 무한 운영을 전제로 나머지 기획을 진행하도록 결정했다.
- 사용자는 낮 영업 중 손님을 클릭하면 손님별 대화 선택지 3개가 나타나고, 이를 통해 성격과 사연을 파악하는 기능을 추가하도록 요청했다.
- 대화 완료 시 해당 손님의 기다림·분노 게이지가 조금 감소하며, 같은 손님에게는 하루 한 번만 사용할 수 있어야 한다는 제약이 추가됐다.

## 3. Codex의 기여

- 특별 주문 콘텐츠의 핵심 문장을 `손님에게 지금 부족한 태도를 가진 반대 성격의 영혼을 건넨다`로 정리했다.
- 맛은 영혼의 `핵심 마음`, 굽기 상태는 영혼의 `행동 방식`을 정한다는 2축 규칙을 제안했다.
- 기존 8가지 맛에 다음 성격 의미를 연결했다.
  - 팥: 초심과 다시 시작
  - 슈크림: 자기 돌봄과 즐거움
  - 초코: 놀이와 상상력
  - 크림치즈: 다정한 감정 표현
  - 피자: 욕구와 취향의 직접 표현
  - 민트: 남과 다른 선택
  - 고구마: 관계와 한자리에 머무는 힘
  - 녹차: 현재를 받아들이고 새로 출발하는 마음
- 굽기 상태를 `말랑 / 노릇 / 바삭`의 유효한 성격 구간으로 나누고, 설익음과 완전히 탄 상태는 별도 조리 실패로 구분했다.
- 하루 최대 한 명 등장, 일반 방문 횟수와 레시피 해금을 이용한 후보 조건, 실패 후 2일 대기, 장기간 미등장 방지 규칙을 포함한 무한 운영용 특별 손님 흐름을 작성했다.
- 낮 대화창의 열림 조건, 하루 한 번 제한, 대화 주제 수집, 게이지 감소, 붕어빵 전달과 클릭의 우선순위 및 일일 초기화 규칙을 작성했다.
- 대사를 읽는 동안 불이익을 받지 않도록 대화창이 열려 있을 때 게임 진행을 잠시 멈추고, 대화 완료 시 대상 손님의 기다림 게이지를 기본 10%p 낮추는 조정 가능한 초깃값을 제안했다.
- 8명의 손님에게 각각 3개씩 총 24개의 낮 대화 선택지와 답변을 작성하고, 세 주제를 모두 들으면 특별 주문 후보가 되도록 기존 등장 조건과 연결했다.
- 기존 3명과 신규 5명을 포함해 다음 8명의 상세 콘텐츠 초안을 작성했다.

| 손님 | 이야기 주제 | 정답 영혼 |
| --- | --- | --- |
| 정현 | 타인의 일까지 떠안아 사라진 자기 시간 | 칼퇴대장 크림붕 |
| 하영 | 안전한 정답만 고르느라 비어 버린 자기 진로 | 샛길요정 민트붕 |
| 미주 | 친구에게 맞추다 잊어버린 자기 취향 | 취향선언 피자붕 |
| 선자 | 추억을 지키려다 멈춰 버린 현재 | 오늘출발 말차붕 |
| 건우 | 너무 빨리 의젓해지며 놓친 놀이와 도움 요청 | 놀자대장 초코붕 |
| 태수 | 딸에게 사과와 애정을 말하지 못하는 아버지 | 먼저안아 치즈붕 |
| 나리 | 버려지기 전에 먼저 떠나는 관계 습관 | 한자리 고구붕 |
| 준호 | 최고가 아니면 새 일을 시작하지 못하는 은퇴 선수 | 첫판환영 팥붕 |

- 각 손님에 대해 기본 정보, 평소 방문 대사, 특별 주문 대사, 정답 영혼, 반대 관계, 성공 이야기 3~4컷, 가까운 정답 힌트와 해금 후 대사를 작성했다.
- 손님 도감과 최대 24가지 맛·굽기 조합의 영혼 도감 구조, Unity에서 저장할 콘텐츠 데이터 항목, 아트와 UI 재사용 기준을 문서에 포함했다.

## 4. 사람이 직접 판단하거나 수정한 부분

- 사용자가 이야기 손님 수를 3명 수준의 작은 MVP가 아니라 총 8명으로 확정했다.
- 사용자가 하루 마지막에 특정 손님 한 명이 들어오고, 그 손님에게 붕어빵 하나만 건넬 수 있다는 핵심 흐름을 정했다.
- 사용자가 완벽한 붕어빵만 성공하는 방식 대신 맛과 굽기 상태에 따라 영혼이 달라지는 방식을 선택했다.
- 사용자가 손님과 붕어빵 영혼의 성격이 서로 반대되는 관계를 콘텐츠의 재미로 정했다.
- 사용자가 5일차 종료와 반복 회차 구조를 사용하지 않고, 영업일이 계속 증가하는 무한 운영으로 변경하기로 결정했다.
- 사용자가 낮 영업 중 손님 클릭으로 말을 걸고, 손님마다 제공되는 대화 선택지 3개를 통해 특성과 사연을 알아내는 방식을 결정했다.
- 사용자가 대화 완료 시 해당 손님의 기다림·분노 게이지가 감소하고, 같은 손님에게는 하루 한 번만 효과를 받을 수 있도록 정했다.
- Codex가 제안한 `손님의 문제를 붕어빵이 치료한다`는 표현은 사용하지 않고, 손님이 작은 행동을 선택하도록 돕는 이야기로 정리했다.

## 7. 실패 또는 배운 점

- 처음에는 일주일 MVP를 고려해 손님 3명과 짧은 이야기만 구현하는 범위를 제안했지만, 사용자가 손님 8명을 명확히 선택해 전체 설계를 확장했다.
- 기존 5일 운영을 유지하면 하루 한 명의 특별 주문만으로 한 저장 데이터에서 8명을 만날 수 없다. 반복 회차를 사용하는 안을 잠시 고려했으나, 사용자가 무한 운영을 선택해 등장 규칙과 저장 전제를 바꿨다.
- 맛 8종과 굽기 3종의 모든 조합을 고유 아트로 만들면 제작량이 커진다. 정답 영혼 8종만 고유 이름과 소품을 사용하고 나머지는 공통 몸체와 조합 규칙을 재사용하는 방향이 필요하다.
- 손님의 고민이 서로 달라도 결말이 모두 교훈적인 대사로 끝나면 비슷해질 수 있다. 구현 단계에서 대사 길이를 줄이고, 각 손님의 작은 행동이 시각적으로 다르게 보이게 점검해야 한다.
- 대화 보상이 너무 크면 주문 처리 난도를 무력화하고, 너무 작으면 플레이어가 대화를 건너뛸 수 있다. 하루 한 번 제한과 10%p 초깃값은 실제 플레이 테스트로 조정해야 한다.

## 8. 기여 효과

- 대화 중 흩어져 있던 아이디어를 구현자가 사용할 수 있는 하나의 콘텐츠 기획 문서로 정리했다.
- 8명의 연령, 생활 영역, 고민, 성공 행동을 비교해 이야기 중복을 확인할 수 있게 됐다.
- 상점의 레시피 해금, 무한 운영, 특별 주문, 손님 도감과 영혼 도감이 하나의 장기 플레이 흐름으로 연결됐다.
- 낮 대화가 이야기 단서 수집과 주문 운영 보상을 동시에 제공해, 손님을 기다리는 대상이 아니라 알아 가는 캐릭터로 보이게 하는 기준이 추가됐다.
- 아직 구현되지는 않았지만, 이후 Unity 데이터 구조와 UI·아트 제작 범위를 나눌 수 있는 기준을 마련했다.
