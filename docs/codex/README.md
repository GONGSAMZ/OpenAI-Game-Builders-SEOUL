# Codex 활용 기록 안내

이 폴더는 우리 팀이 Codex와 함께 게임을 만든 과정을 남기는 공용 기록 공간입니다. 목적은 대화 전체를 보관하는 것이 아니라, **실제 게임 결과로 이어진 Codex 협업 사례**를 나중에 증명하는 것입니다.

## 기록 흐름

```text
작업 완료
  → 작업 기록 1개 작성
  → 하루 종료 시 일일 요약
  → 마감 전 대표 사례 3~5개를 최종 문서로 정리
```

## 팀원 규칙

1. 기능 하나가 실행·검증 가능한 상태가 되었을 때만 작업 기록을 남긴다.
2. 각 팀원은 하루 1~2개의 중요한 기록이면 충분하다.
3. Codex가 작성한 것과 사람이 결정·수정·검증한 것을 구분한다.
4. 스크린샷은 `Codex 요청/응답` 1장과 `게임 실행 결과` 1장을 우선 남긴다.
5. API 키, 계정 정보, 개인 이메일은 캡처 전에 가린다.

## 폴더 사용법

| 경로 | 용도 |
|---|---|
| `templates/` | 새 기록을 만들 때 복사하는 양식 |
| `logs/` | 기능·문제 해결 단위의 원본 기록 |
| `evidence/codex/` | 중요한 Codex 대화 캡처 |
| `evidence/game/` | Unity 실행 결과, 전후 비교 이미지 |
| `daily/` | 하루 단위 진행 요약 |
| `CODEX_JOURNEY.md` | 심사용 최종 정리 문서 |

## 빠른 사용법

작업을 마친 뒤 Codex에게 다음 요청을 한다.

```text
Use $codex-worklog to record the task I just completed.
Task ID: <작업 ID>
Member: <이름>

현재 대화와 실제 변경 내역에서 확인되는 사실만 사용하고,
사람이 직접 판단하거나 검증한 내용은 구분해서 작성해줘.
```

이 저장소를 열어 둔 Codex는 `.agents/skills/codex-worklog/`의 스킬을 자동으로 찾는다. 목록에 바로 보이지 않으면 Codex를 다시 시작한 뒤, 채팅에서 `@`를 입력해 `Codex 작업 기록`을 선택한다.

## 팀 공유 방법

1. 이 프로젝트를 GitHub 저장소에 올린다.
2. 팀원에게 저장소 초대 링크를 보낸다.
3. 팀원은 저장소를 복제한 뒤 프로젝트 루트 폴더를 Codex에서 연다.
4. 각자 Codex 채팅에서 `@` → `Codex 작업 기록`을 선택해 사용한다.

스킬과 기록 폴더가 모두 Git으로 공유되므로, 누군가 스킬 또는 템플릿을 개선하면 다른 팀원은 `git pull` 후 같은 내용을 사용하게 된다.

## 작업 파일 이름

`logs/YYYY-MM-DD-이름-작업ID.md`

예시: `logs/2026-08-15-hyeyeon-STORM-01.md`
